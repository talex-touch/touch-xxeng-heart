# 竞品评审与收敛决策

日期：2026-09-03 · 对应版本：v0.3.1

这份文档记录一次竞品评审的结论和由此确定的方向调整。它不描述现有功能（那在 [GUIDE.md](./GUIDE.md)），只回答两件事：**接下来不做什么，以及为什么。**

---

## 结论

Lexi 的功能面已经超过除沉浸式翻译外的全部竞品，**当前瓶颈是配置密度，不是功能缺口**。此后以收敛为主，新增能力必须能说明它替代掉了哪个旧配置项。

三条具体判断：

1. 「逐句精读侧栏」不做——竞品已经验证过并放弃了这个形态
2. 视频字幕不做——最贵的战场，且不是 Lexi 的差异化
3. 有一个安全默认值必须先改，优先级高于以上所有

## 二、不做逐句精读侧栏

### 竞品已经砍掉了它

Read Frog 官网截图里的「深入学习」侧栏（Sentence 1/2/3 + Key Words + Explanation + 水平档位 + Regenerate）在其 **v1.46.7 当前源码中已不存在**。

核对证据：

- `keyWords` / `articleAnalysis` / `readArticle` 全仓库 grep 零命中
- CHANGELOG PR #982：`remove read provider and unify per-feature provider model`
- CHANGELOG PR #1166：`Remove the deprecated Selection Toolbar AI button / Vocabulary Insight feature and keep Dictionary custom actions as the supported replacement`
- `src/entrypoints/sidepanel/` 现仅剩 `main.tsx`；`side.content/` 仅剩悬浮按钮

作者的重心已转向 `subtitles.content/`（29 个文件的完整字幕管线）、Notebase 生词本、Dictionary custom actions。做到 v1.46 才砍，这是投入换来的结论。

### 为什么它不成立

以下为推断，非作者公开说明：

- **成本按篇计**。整篇文章逐句生成 Key Words + Explanation，自带 key 的用户付不起
- **命中率低**。一篇文章真正卡住的可能只有 3 句，其余的生成是纯浪费
- **违反第一设计原则**。[PRODUCT.md](../PRODUCT.md) 写的是「留在阅读流里」；视线一旦移到右侧栏逐句读，就已经离开正文了

Lexi 现有的**划词卡片本身就是按需触发的逐句精读**，形态优于全文批量。

## 三、要抄的是水平档位，不是侧栏

截图顶部三个选择器 `English → Simplified Chinese → Intermediate`，前两个是语言，**第三个是水平档位**——解释颗粒度随用户水平变化。这是 Read Frog 做对且 Lexi 尚未做的唯一一件事。

对 Lexi 而言这不是新功能，是一个 prompt 参数：

- 现状：9 级学习等级只喂给了「网页词汇替换」
- 缺口：划词卡片的术语解释、实体检测的释义，都没有接入这个等级
- 落地：把等级注入这两处的 prompt。**零新增 UI，零新增配置项**

这一项的价值在于它换来了把「9 级 × 5 密度」那堆配置收掉的资格——等级一处定义，多处消费。

## 四、必须先改的安全默认值

**`同步中包含 API Key` 默认开启**（见 [GUIDE.md](./GUIDE.md) 隐私与数据一节）。

开启同步后，API Key 会随配置上传到浏览器厂商的同步服务器，当前只用文档提示用户自行关闭。

这不是配置项数量问题，是默认值把用户置于风险中。安全默认不应交给用户承担。

**改法**：默认关闭；用户主动开启时给一次明确的风险确认。

**优先级高于本文档其余全部事项。**

## 五、配置收敛清单

现状证据：`src/options/Options.vue` 2528 行，`src/contentScripts/pageEnhancer.ts` 5204 行。[PRODUCT.md](../PRODUCT.md) 的反参照写着「不做重型开发者面板」，实现走了反方向。

| 现在 | 收敛为 |
|---|---|
| 整页翻译 5 种触发方式 | 留 2 种：页面浮标 + 侧边栏。移除「无选区时 360ms 内连按两下 Ctrl/Alt」——误触温床 |
| 启动范围 4 选（仅本次 / 链接 / 站点 / Regex） | 2 选：仅本次 + 这个站点一直翻。Regex 收进高级设置 |
| 词汇替换 9 级 × 5 密度 × 3 显示方式 × 上限 1–80 | 3 档（轻 / 中 / 重）。密度与上限从学习等级自动推导 |
| 按域名 × 6 场景的开关矩阵 | 移除。保留全局开关 + 黑名单 |
| 限额 4 维度（日上限 / 滚动窗口 / 时段 / 每引擎） | 1 个「每日预算」 |
| 3 套速读卡片各 4 项配置 | 1 个开关，其余用默认值 |

判断依据：**每个配置项都是一次没有做出的产品判断。** 9 级 × 5 档 = 45 种组合，团队不可能全部验证，用户也不可能选对。

---

## 六、字幕：contract 保留，暂不投入

`src/logic/subtitles/`（commit 21c7ffa）的抽象设计是干净的——provider 分层、抛错等同于声明放弃并降级到下一源、AI 转录作为最低优先级且标记 billable。**保留，不动。**

暂不投入的理由：Read Frog 已在此投入 29 个文件的工程量并默认开启，Trancy 以此为付费卖点多年。这是最贵的战场，且与 Lexi 的技术阅读定位无关。
